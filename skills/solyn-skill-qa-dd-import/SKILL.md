# solyn-skill-qa-dd-import

## 执行方式（混合）

1. **确定性解析（默认）**：`src/skills/index.ts → qaImport` + `src/lib/import/engine.ts`。
2. **Claude 兜底**：表头无法确定性匹配且配置了 Anthropic Key 时，把未匹配表头与可用字段交给 Claude，本文件作为 system prompt，只返回 JSON 映射。

## 模板结构（List v1）

工作簿含工作表「Q&A」：第 1 行为表头，第 2 行起为数据。

### 列 → 字段

| 列 | Excel 表头 | 字段 key | 类型 | 语义角色 | 说明 |
|---|---|---|---|---|---|
| A | # | code | 文本 | 编号 | **匹配键**，数字 1、2、3… 按文本存储、自然排序；手工新增留空时自动取最大号 + 1 |
| B | 权限组 | access_group | 下拉 | 权限组 | `ADM` / `SEL` / `EXC` / `DD`，逐级放大（见下）；空值按 ADM 处理 |
| C | 项目阶段 | stage | 文本 | 种类 | 填 FA 项目管理的**任务编号**（如 `P1-01`），PDF 报告按此分组并带出任务名称 |
| D | 提问者 | asker | 下拉 | — | 如 `SOLYN FA`；新值可在导入时补充为选项 |
| E | 提问内容 | question | 多行文本 | 标题 | 中文在上、日文在下；**非空即为数据行** |
| F | 确认目的与论点 | purpose | 多行文本 | — | 表头前可能带空格，匹配时忽略空白；★ 表示重要度 |
| G | 回复状态 | status | 下拉 | 状态 | 见下 |
| H | 提问对象 | respondent | 下拉 | 负责人 | 如 `CEO`；与提问者共同构成「问答双方身份」 |
| I | 回答记录 | answer | 多行文本 | — | |
| J | 备注 | remark | 多行文本 | — | |
| K | 关联访谈记录 | interview_ref | 文本 | — | 可填知识库中 .md 文件名，知识库中可直接打开 |
| L | 关联材料 | material_ref | 文本 | — | 填 DD 材料前缀编码（如 `S2-Fin-Acct-01`） |
| M | 更新日期 | update_date | 日期 | — | 导入时以文件为准；网站上手工修改时自动更新为当天 |

### 回复状态（G 列下拉）

`未答复`、`待跟踪`、`已解决`、`已无效`

- 已解决 = 完成；待跟踪 = 进行中；未答复 = 未开始；已无效 = 不计入分母
- **解决率 = 已解决 ÷（问题数 − 已无效）**

### 权限组（逐级放大）

ADM（卖方 FA，管理员）> SEL（卖方及其顾问）> EXC（独家谈判对象）> DD（买方尽调顾问）。
标为 DD 的记录，DD / EXC / SEL / ADM 都能看；标为 EXC 的记录 EXC 及以上可见，DD 不可见。
BID1 / BID2 等不在体系内的账户看不到 Q&A。导出 Excel / PDF 时只包含导出人有权阅读的记录。

## 解析规则

1. 工作表：优先「Q&A」，否则按表头关键词得分选择；表头行取前 20 行中命中关键词最多的一行。
2. 表头匹配：字段名全等 → 别名全等（`#` → 编号）→ 近似 → Claude。
3. 数据行：提问内容非空即为数据行；编号缺失的行跳过并提示；重复编号仅保留第一条。
4. 权限组统一转为大写。
