# solyn-skill-fa-pm-import

## 执行方式（混合）

1. **确定性解析（默认）**：`src/skills/index.ts → faPmImport` + `src/lib/import/engine.ts`。标准模板无需调用大模型。
2. **Claude 兜底**：若有表头无法按「字段名 / 别名 / 近似」匹配，且全局后台配置了 Anthropic Key，系统把**未匹配的表头**与**尚未占用的字段**发给 Claude，本文件作为 system prompt。Claude 只返回 JSON 映射，不接触数据行。

### 任务从属关系

任务编号即层级：

| 编号 | 等级 | 上级 |
|---|---|---|
| `P0-00` | 阶段任务（Phase 0） | 无 |
| `P0-01`、`P0-02`… | 一级任务 | `P0-00` |
| `P0-02.1` | 二级任务 | `P0-02` |

等级之间的从属关系在「项目管理 → FA 任务字段 → 任务等级 → 等级从属关系」配置，默认：一级任务 → 阶段任务，二级任务 → 一级任务。

导入时逐行校验（以文件 + 网站现有记录为准），不符合时在预览的「提示」中列出，不阻止导入：
1. 编号不符合 `前缀数字-两位数字(.数字)*` 格式；
2. 编号层级与任务等级不一致（如 `P0-02.1` 标成一级任务）；
3. 上级任务不存在；
4. 上级任务的等级与配置的上级等级不一致。

网站手工新增 / 修改任务时，同样的规则为强校验（不满足无法保存），并禁止重复的任务编号。

### 状态值（M 列下拉）

`未着手／未开始`、`進行中／进行中`、`完了／已完成`、`保留／暂缓`、`中止／取消`

- 完成：`完了／已完成`；不计入完成率分母：`中止／取消`
- 完成率 = 已完成 ÷（总数 − 中止）

### 计算规则（与 Excel 公式一致）

- 计划开始日 = 项目开始日 + 開始D+
- 计划完成日 = 项目开始日 + 開始D+ + 所要日数 − 1
- 延迟天数：已完成 → 実績完了日 − 計画完了日（未填实绩为 0）；未完成且非中止 → max(0, 今天 − 計画完了日)；否则 0

## 解析规则

1. 工作表：选表头命中关键词最多的工作表（No. / Phase / 任务 / ステータス / 進捗率 …）。
2. 表头行：前 20 行中命中关键词最多的一行。
3. 表头匹配顺序：字段名全等 → 别名全等 → 近似（前缀或以「／」分隔的任一部分相同）→ Claude。比较前做 NFKC、去空白与换行。
4. 单元格取值：公式取缓存结果；富文本拼接；日期转 `YYYY-MM-DD`；文本去首尾空白、保留换行。
5. 数据行：`code` 或 `task` 非空；缺 `code` 的行跳过并提示；重复 `code` 仅保留第一条。
6. 元数据：在表头以上区域寻找「プロジェクト開始日 / 项目开始日」，取其右侧第一个日期作为项目开始日，导入确认时可同步到项目。

## 差异与写入

- 按 `code` 与网站记录（external_key）比对：文件有、网站无 → 新增；两边都有且字段值不同 → 更新（只比较文件中存在的列，计算列除外）。
- **合并**模式不删除；**完全同步**模式删除网站中存在但文件里没有的记录（软删除，可恢复）。
- 默认「空单元格不覆盖网站已有值」，防止旧文件清空网站里后填的实绩。
- 下拉值不在选项内：默认自动加入字段选项。
- 所有写入 `source = import`，逐条写变更日志并更新字段级更新时间。

## Claude 映射输出格式

仅输出 JSON，不要解释：

```json
{"mappings":[{"col":7,"fieldKey":"start_offset"},{"col":19,"fieldKey":null}]}
```

判断依据：中日文同义（例：「担当」=负责人，「所要日数」=工期天数，「成果物」=交付物）；带括号注释的表头按主体词判断；无法确定给 `null`，不要猜测。
